### Finding: the Claude CLI rewrites `settings.json`

In every cell with a real `claude`, installing the plugins makes the CLI rewrite `~/.claude/settings.json` (same content, other key order and whitespace, e.g. `includeCoAuthoredBy` and `alwaysThinkingEnabled` move). `chezmoi diff` is then not empty and a plain second
`chezmoi apply` stops with `.claude/settings.json has changed since chezmoi last wrote it?` and, without a TTY, `could not open a new TTY` (exit 1). This is the existing risk R2 (a fully managed file), not caused by this PR, but it means the plan's
"second apply exit 0, empty diff" does not hold with the real Claude CLI. The native test therefore asserts: JSON content equal to the managed render, the failure is exactly this conflict and the diff touches no other file (printed as `KNOWN …`), then `chezmoi apply --force` exits 0 and the diff is empty.
The stub layer cannot show this. Fixing it structurally (a merging `modify_` script for `settings.json`) is out of scope for PR-5 and needs a decision; the runbook documents the workaround (step 4) with a backup first.
